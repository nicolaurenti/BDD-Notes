# Instrucciones del baúl de Obsidian

- Siempre que se cree, modifique, renombre o elimine un archivo de este baúl, guardar los cambios en Git mediante un commit y hacer push al remoto antes de dar la tarea por terminada. Agrupar en un commit los cambios de una misma tarea.
- El usuario consulta este mismo proyecto desde su tablet y hace pull después de los cambios realizados aquí; mantener el remoto actualizado es parte de completar cada tarea.
- Revisar el diff antes de confirmar. Si el remoto tiene cambios, integrarlos conservando el trabajo local. No usar force push ni descartar cambios para sincronizar.
- Si el commit o el push falla, informar que la sincronización quedó pendiente y el motivo; no afirmar que los cambios están disponibles en la tablet.

## Criterio para los apuntes teóricos

- Los apuntes se usan para resolver los prácticos y preparar el examen: priorizar enunciados y filminas de la cátedra, con su terminología y sintaxis. No reemplazarla por formas modernas; en los triggers usar EXECUTE PROCEDURE como en la plantilla del TP4.
- Cada práctico debe poder estudiarse con sus propios contenidos y los anteriores. No adelantar temas ni remitir a prácticos posteriores como requisito para entender o resolverlo.
- Desarrollar definiciones, razonamiento y ejemplos con resultados cuando sean necesarios. Evitar tanto las listas telegráficas como el relleno. Indicar supuestos y explicar por qué funciona la solución o falla el caso inválido.
- Diferenciar SQL-1999 de PostgreSQL cuando la consigna lo pida; no mezclar ambos como si fueran el mismo criterio. Conservar las discrepancias de las fuentes y explicarlas sin corregirlas en silencio.
- Mantener temas relacionados agrupados, sin crear notas innecesarias. No reescribir las resoluciones personales al revisar teoría salvo pedido explícito.
